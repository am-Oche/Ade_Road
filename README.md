# AdeRoad — Expo mobile app prototype

**AdeRoad is a placeholder for your friend’s company name.** This is an actual React Native + TypeScript source project, not a website or a webview. Its goal is to demonstrate a Nigerian roadside-assistance customer and provider journey on a phone through Expo Go.

> Implementation status: the source and test files are written. This workspace has no Node shell, Metro, native emulator, or Expo Go runtime. Dependencies have **not been installed**, TypeScript/Jest have **not been run**, and phone rendering has **not been visually verified** here. Treat native verification as an outstanding handoff step, not a passed test.

## Run on a phone

Prerequisites: Node.js 20.19.4+ (or a supported newer LTS), npm, and an Expo Go client compatible with **Expo SDK 54**. This project pins React 19.1 / React Native 0.81.5 and SDK-54-compatible native packages.

```sh
# From this repository, on your own computer:
npm install
npx expo install --fix
npx expo-doctor
npm run typecheck
npm test -- --runInBand
npx expo start --go --clear
```

Scan the Metro QR code with Expo Go on Android or your iPhone camera. Keep phone and computer on the same network. If LAN discovery fails, try `npx expo start --go --tunnel` (Expo may request its tunnel dependency; internet is required).

**SDK compatibility matters:** Expo Go's store version may support a newer SDK only. Check <https://expo.dev/go> for matching clients. Android supports installing a compatible Expo Go APK. On a physical iPhone, if the available Expo Go no longer supports SDK 54, upgrade the project to the SDK supported by that client using the official upgrade guide before running it: <https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/>. `expo install --fix` aligns dependencies within the installed SDK; it does not upgrade the SDK itself. A native development build is an alternative but is outside this Expo Go handoff.

No API key, server, or real OTP account is needed for the demo. Maps and network simulation need connectivity; history and saved settings remain local. Map tiles in Expo Go use the host app’s map configuration. A future standalone Android build needs its own properly configured map-provider credentials.

**Do not use this workspace’s website preview or Publish tab to run the app.** There is intentionally no `index.html`, website build, or hosted deployment. The only launch address is the `exp://…` development URL generated by your local Expo process.

### First demo run

1. Open the app and choose **Let’s get you moving**.
2. Enter a structurally valid Nigerian mobile number (`+234`, local `0`, or 10-digit mobile form). No SMS is sent.
3. Enter the displayed demo OTP **123456**, or tap **Fill demo code**. Challenges expire after five minutes. Resend has a 30-second cooldown. If Metro reloads the app on this screen, resend to create a new in-memory challenge.
4. Pick a service, add vehicle details, and use the labelled sample pickup, your phone’s position, or manually entered coordinates.
5. Review the naira estimate and acknowledge that dispatch is simulated.
6. Watch the marker move. About 65 seconds of foreground/online demo time leads to arrival; the ETA is illustrative, not wall-clock routing.
7. Choose **Finish demo assistance & pay**, select transfer/card/cash, and simulate payment.
8. Rate the experience, share the clearly labelled demo receipt, and open History.
9. In Settings, enable **Provider mode** to reveal the Provider tab.
10. Use a consenting emergency contact if testing real SOS sharing. Never send surprise SOS messages to anyone.

## Implemented features

### App foundation
- Expo configuration, strict TypeScript, typed React Navigation native stack and bottom tabs.
- Reusable cards, inputs, buttons, skeletons, error/retry components, status pills, safe-area and keyboard handling.
- Emerald `#0B6B3A`, amber `#FFB400`, off-white `#F6F8F6`; red `#E5322D` reserved for SOS/errors.
- System/light/dark preferences, dark navigation, native map styling, saved preferences.
- Local boot recovery and app-level render error fallback.

### Customer journey
- Welcome, Nigerian phone normalization, mocked OTP challenge, resend, expiry, invalid-code error, and local demo session.
- Six services: tow truck, jump start, flat tyre, fuel delivery, engine trouble/mechanic, and lockout.
- Request details, vehicle/notes, pickup map, foreground GPS permission, manual coordinate fallback, and explicit demo-location labels.
- Price estimate with service fee and dispatch fee in ₦; simulation acknowledgment required before booking.
- One active customer request at a time, duplicate-submit guards, local cancellation.
- Simulated moving provider on a native map, relative route, decreasing example ETA, arrival state, provider card and contact buttons.
- Mock transfer/card/cash payment; no card details, real accounts, actual transfers, charges or gateway integration.
- Payment state transition checks and local duplicate-payment protection.
- Receipt, five-star rating, feedback, native receipt sharing and filtered request history.

### SOS and contact handoff
- SOS is available before and after mock login.
- One tap on an SOS entry starts a fresh location lookup and opens the native share sheet. OS permissions and recipient/send confirmation are still required.
- Saved emergency contacts have individual **Text SOS** actions that prepare an SMS composer with fresh coordinates.
- Permission denied/GPS timeout recovery, phone-settings handoff, known-coordinate entry and location-free text fallback.
- **SOS never falls back to demo pickup coordinates.** The app does not silently send messages, verify delivery, contact emergency services or track in the background.
- Provider Call/WhatsApp buttons are safe by default: no made-up numbers are dialled. Configure a consenting test number in Settings to launch actual phone/WhatsApp handoffs after confirmation.

### Provider demo
- Settings toggle reveals a provider tab; no real role authorization is implied.
- Sample incoming jobs, accept/decline, accepted state, explicit completion, sample earnings and reset queue.
- Provider sample jobs are independent from customer requests. They are not two real devices exchanging jobs.

### Weak-network handling and storage
- Animated service/map skeletons, loading buttons, retry errors, actual NetInfo offline banner and a bundled service catalogue fallback.
- Failed request forms retain values while their screen is mounted. Unsubmitted drafts are **not** persisted across app restarts.
- Offline request/payment/provider operations are rejected before changing state; interrupted mock operations can be retried without charging money.
- Tracking pauses while offline, signed out, or backgrounded. No background tracking permission is used.
- Persistent requests, ratings, contacts, provider jobs, local session and theme via AsyncStorage.
- Serialization of storage writes, local save-failure banner with retry, boot-load retry and reset recovery.
- Settings controls: **Simulate offline** and **Fail next mock request**. These affect only demo network operations, not real SMS/GPS/sharing.

## Data models, structures and storage

All contracts are in `src/types.ts`.
- `Service`: id, display label, icon, fee, demo ETA.
- `RequestDraft`: service, pickup coordinates/source/label, vehicle, notes.
- `RoadRequest`: draft, timestamps, quote, status, animation progress, optional payment/rating/review.
- `ProviderJob`: local sample customer/job and incoming/accepted/declined/completed state.
- `EmergencyContact`: id, name, Nigerian mobile number supplied by the user.
- `Settings`: theme, provider mode, emergency contacts, optional consenting test-provider phone.

AsyncStorage key: **`@aderoad/demo/v1`**, containing `{ version, phone, settings, requests, jobs }`. AsyncStorage is not app-encrypted. No API keys or payment details are stored. Phone numbers, pickup coordinates and contacts should be treated as sensitive in a production app. This demo is single-device storage, not a secure per-user account store: signing in under another demo number sees the same data. Sign out retains local data; Reset removes it and restores the sample fixtures.

Mock OTP challenges exist only in process memory and are deliberately insecure. All sample service prices, providers, initial history, initial provider jobs, route offsets, OTP/timing constants and transfer display data live in **`src/data/mockData.ts`**. Unit-test inputs are separate test vectors, not production demo contacts.

No REST Table API, hosted database, Cloudflare D1, R2, authentication server, or remote storage is used.

## Public URLs and external handoffs

- Production app / website URL: **none**.
- Backend API endpoints: **none**.
- Expo launch URI: `exp://<your-computer>:<Metro-port>` (assigned when starting Expo; not published by this workspace).
- Native device handoffs: `tel:<configured-test-number>` and `sms:<emergency-contact>?body=…` / iOS body delimiter.
- WhatsApp handoff: `https://wa.me/<configured-test-number>?text=…`.
- Location link included only when the user shares: `https://maps.google.com/?q=<latitude>,<longitude>`.
- Map tiles are supplied by the native map provider in Expo Go and require their network service.
